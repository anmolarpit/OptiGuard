# Database

## Overview

The database serves as the persistent storage layer of OptiGuard. It stores user information, command history, telemetry, alerts, audit logs, and system events, ensuring that all operational and security-related data is available for monitoring, analysis, and reporting.

## Responsibilities

* Store user accounts and roles
* Record all operator commands
* Store telemetry received from the hardware controller
* Maintain system alerts
* Maintain audit logs
* Record system events
* Support data retrieval for the dashboard and backend services

## Database Management System

**PostgreSQL**

PostgreSQL was selected for its reliability, ACID compliance, scalability, and strong integration with Spring Boot through Spring Data JPA.

## Database Tables

### Users

Stores authenticated system users and their assigned roles.

Typical fields:

* User ID
* Name
* Email
* Password
* Role

---

### Commands

Stores every command issued through the dashboard.

Typical fields:

* Command ID
* Command Type
* Operator
* Authentication Status
* Execution Status
* Timestamp

---

### Telemetry

Stores sensor readings received from the hardware controller.

Typical fields:

* Telemetry ID
* Voltage
* Current
* Physical Switch State
* Servo State
* Sensor Status
* Timestamp

---

### Alerts

Stores security and hardware alerts generated by the detection engine.

Typical fields:

* Alert ID
* Severity
* Alert Type
* Description
* Resolution Status
* Timestamp

---

### Events

Stores important system state transitions.

Typical fields:

* Event ID
* Event Type
* Previous State
* Current State
* Trigger Source
* Timestamp

## Relationships

* One User can issue multiple Commands.
* Commands may generate Alerts.
* Telemetry records are stored independently as time-series data.
* Events maintain a complete history of system state transitions.

## Integration

The database is accessed exclusively through the Spring Boot backend using Spring Data JPA.

Direct access from the frontend or hardware controller is not permitted.

## Backup Strategy

Regular database backups should be maintained throughout development to prevent data loss during testing and integration.

## Version Control

* `schema.sql` contains the database schema.
* `seed.sql` contains sample data for development and testing.
* Future schema updates should be managed through version-controlled migration scripts.
